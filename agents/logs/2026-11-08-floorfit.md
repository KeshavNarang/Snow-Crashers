# Floor-fit orientation gate (evals first) 2026-11-08, branch agent/sensor-floorfit

Bug (from agents/logs/2026-11-07-depth.md): `fit_floor` took the plane with the most inliers; on a glossy
table the table and a box face tie and frames flip, giving a ground height of ~0.28 m instead of 0.10 m.

## Evals written first (`team_ws/src/overwall_nav/test/test_floorfit.py`, 10 tests)
- table + box: 40 frames must all return the floor; the same scene WITHOUT the prior must go wrong in
  some frames (guards against an eval that passes by accident); floor alone still fits at 0.10/0.5/0.85 m;
  a wall alone is not a floor; mount +-10 deg off still fits; a 60 deg mount reads as "no fit", not
  silently bent to 27; no prior = old behaviour.
- End to end through the real StereoRig: realistic geometry (strict, repo tolerance 0.03 + 0.03 h, 4 deg);
  hard near-wall geometry (camera 0.10 m up, wall 0.45 m ahead) must return the floor, not the wall
  (data-limited accuracy: worst 5 cm / 9.8 deg; old code returned the wall: 112 deg, 0.45 m).
- Run on the current code first: 6 errored (no such parameter), the 2 old-behaviour evals passed and so
  confirmed the bug reproduces.

## Fix
`fit_floor(..., pitch_deg=None, max_tilt_deg=12)`: candidate planes must be within 12 deg (pitch and roll)
of the mount pitch; candidates generated and gated vectorised; only gate survivors count against the
iteration budget. `stereo_depth_node` passes its `camera_pitch_deg`. No prior = unchanged behaviour.

## What did not work (kept honest)
- Gate widths 25 / 8 deg: 25 left a tilted plane in the hard scene, 8 broke the +-10 deg mount case.
- A per-candidate Python loop with the gate starved the search (some seeds -> no fit) and then cost 36 ms
  per fit; vectorising brought it back to the original ~6 ms (laptop).
- I first set the end-to-end tolerance too tight (3 cm flat, my guess) and then aligned it to the repo's
  own convention; the hard case is judged on "floor not wall" with margin.

## Results
- Laptop: 53/53 tests pass (stereo, floorfit, mission, checks, yaw). Realistic geometry worst error
  1.2 cm / 0.7 deg (was 4.0 cm / 2.3 deg with 80 iterations).
- Jetson (aarch64, OpenCV 4.5.4, scratch copy in the container, stack up 19 min): floorfit 10/10, stereo
  10/10; fit_floor median 27.9 ms with the prior vs 28.8 ms without. Not deployed to ~/team_ws.
- Side finding: fit_floor is ~28 ms of the ~63 ms per depth frame on the Jetson.

## Speed-up of fit_floor (evals first), same day
Profile (laptop, 30k points, 60 fits): SVD 58 % of a fit (np.linalg.svd of an N x 3 matrix builds an N x N U),
scoring the 80 candidates 2.9 ms of 6.4 ms, everything else small.
Evals written and run first (`test/test_floorfit_speed.py`, 7 tests): same plane as a FROZEN copy of the old
function on 3 scenes x 12 seeds x with/without the prior; >= 1.5x faster than the frozen copy in the same
process (best of 25); degenerate inputs (too few, identical, collinear points); exact recovery of a
perfect plane; normal sign independence. On the old code only the speed eval failed (5.34 vs 5.46 ms).
Fix: plane normal from the smallest-eigenvalue eigenvector of the 3 x 3 covariance instead of a full SVD.
Result (laptop): 5.8 -> 2.2 ms per fit (2.6x), identical answers; 60/60 tests pass.
NOT yet measured on the Jetson: the drone lock was held by claude/gpu-bench (GPU stereo benchmark), so no
load was added. Expected: fit_floor ~28 ms there, so roughly 15 ms saved per depth frame; to confirm.
